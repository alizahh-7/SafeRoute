# SafeRoute Telangana

SafeRoute Telangana is an explainable, full-fledged civic road-safety intelligence application for journeys in Hyderabad and across Telangana. It is built around a simple premise: conventional navigation optimises for time and distance, while a safety-aware route decision should make crash history, weather, congestion, inundation, road condition, and incident context visible before a driver commits to a corridor.

The project was developed end-to-end — trained model, live backend pipeline, and a complete multi-page product — for the AI Careers for Women (AICW) Capstone Program, supported by Microsoft.

SafeRoute is a decision-support system. 

## Product Capabilities

- Search a Hyderabad/Telangana journey using origin/destination autocomplete and analyze the route.
- Split route geometry into approximately 500m segments and calculate a transparent 0–100 safety score for each segment.
- Inspect the full route on an interactive Leaflet map, including road-level scores, weather, traffic, vision, incident, and advisory context.
- Open a Segment AI Diagnostics page whose displayed factor breakdown is numerically identical to the backend's real additive score — not an illustrative approximation.
- Compare a backend-scored alternate route when it is meaningfully safer within the configured time trade-off, with alternates for every hazard on the route pre-fetched before a simulated drive begins, so the drive never stalls mid-hazard.
- Run a real-time hazard/reroute advisory and route-drive simulation from the currently loaded route data.
- Download a full, multi-page safety report — a plain-language risk band, an executive summary, a page explaining what each of the five fusion signals measures and its blind spots, per-segment cards with exact score math and narrative explanation, risk-distribution and hazard-signal charts, data-driven recommendations, and a limitations page — generated by the same shared explanation engine used on-screen, so the report and the app never disagree.
- Use the Live Analytics & Risk Heatmap workspace to inspect spatial risk, an AI-calibrated diurnal risk forecast, risk distribution with drill-down, an interactive per-signal exposure visualization, active detections, and a full signal-status inventory.
- Track saved corridors over repeated checks, with genuine score-change detection — a road-name/position fallback when segment IDs don't line up between checks (which is almost always, since IDs regenerate per route recalculation) — and clearly distinct labels for a per-check score delta versus the Analytics tab's absolute risk threshold.
- Maintain session-level route/hazard/reroute counters, and the active route itself, persisted across a page refresh — not lost on reload.

## Risk Model

Each route segment is evaluated independently. The backend fuses these components:

| Signal | Source | Contribution / behavior |
|---|---|---|
| Historical crash context | IIT Delhi Telangana-filtered crash data + black-spot CSV | Base historical score using proximity and severity. |
| Day pattern | Crash-data weekday profile | Modifies historical exposure by current day-of-week evidence. |
| Weather | Open-Meteo current precipitation, wind, visibility | Adds 0, 10, or 20 points based on adverse conditions. A clear live reading correctly contributes 0. |
| Traffic | TomTom flow segment current/free-flow speed ratio | Maps to low 0, medium 5, high 12, severe 20 points. |
| Inundation | Static municipal/GHMC-style waterlogging reference coordinates + live weather | Flags only when a segment is near a reference point and weather is adverse. |
| Surface condition | Mapillary imagery where covered, analyzed by YOLOv8; RDD2022 fallback when available | Adds none 0, minor 5, moderate 12, severe 22 points. |
| News | Google News RSS road-name-relevant hazard headlines | Uses urgency/recency-derived score, capped in risk fusion. |

The segment score is capped at 100; the route score is the arithmetic mean of scored segments. Explanations — on-screen and in the exported PDF alike — are generated from the actual contributions recorded on each segment via a single shared narrative engine, not written independently in each place.

## Provider Integrity

SafeRoute does not silently turn failed external calls into safe-looking readings:

- Open-Meteo clear weather appears as live clear / no score lift, not "missing weather."
- TomTom failures or absent credentials appear as traffic unavailable and contribute no made-up traffic risk.
- Mapillary no-coverage falls back to bundled RDD2022 imagery only when that local asset is present; otherwise vision is marked unavailable.
- Google News returning no road-relevant hazard headline is a valid "no relevant reports" result.
- Waterlogging data is a static reference dataset, not a real-time municipal sensor feed.

## Analytics Workspace

Analytics is intentionally based on the loaded route, not a citywide dashboard pretending to have backend aggregation that does not exist.

- **Corridor Heatmap** — segment midpoint risk plotted on the actual current route geometry.
- **Risk Distribution** — Low (0–29), Moderate (30–49), High (50–74), Severe (75–100) counts and percentages from all loaded segments, with bucket selection revealing the represented roads.
- **AI-Calibrated Forecast** — a diurnal (time-of-day) risk curve derived from loaded scores, time bands, and inundation flags.
- **Current Exposure Field** — an interactive layered signal weave: historical, weather, traffic, surface, and incident ribbons vary in thickness by actual per-segment contribution; selecting a segment exposes its road, score, dominant factor, and advisory state.
- **Detection Feed** — active weather, traffic, vision, inundation, and news events only.
- **Signal Inventory** — the complete segment telemetry ledger, including clear and unavailable statuses.

## Backend API

FastAPI entry point: `backend/api/main.py`

| Method | Endpoint | Request | Response |
|---|---|---|---|
| POST | `/route-risk` | `{ origin, destination }` | Route total, scored segments, reroute prompt status. |
| POST | `/alternate-route` | `{ origin, destination }` | Availability, primary/alternate risks, time delta, optional segment lists. |
| GET | `/location-suggestions?q=` | Search query | Nominatim-derived suggestions. |
| GET | `/reverse-geocode?lat=&lon=` | Coordinates | Display label. |
| GET | `/city-news` | None | Hyderabad RSS headlines. |
| GET | `/vision-fallback/:file` | Image filename | Local RDD2022 fallback image when available. |

Frontend API base defaults to `http://127.0.0.1:8000`, overridable via `VITE_API_BASE_URL`.

## Local Setup

### Prerequisites
- Python 3.10+ with a virtual environment
- Node.js 20+ and npm
- Provider credentials for OpenRouteService, TomTom, and Mapillary
- Network access for external providers and map tiles

### Environment

Create a root `.env` file from `.env.example`. The backend explicitly loads this root file, so it works whether Uvicorn is started from the project root or `backend/`.


Never commit `.env` or provider credentials.

### Start the backend

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt

Set-Location backend
..\.venv\Scripts\python.exe -m uvicorn api.main:app --reload --host 127.0.0.1 --port 8000
```

### Start the frontend

In a second terminal:

```powershell
Set-Location frontend
npm install
$env:VITE_API_BASE_URL = "http://127.0.0.1:8000"
npm run dev
```

Open the Vite URL shown in the terminal, normally `http://localhost:5173` or `http://127.0.0.1:5173`.

### Manual route check
1. Run backend and frontend with valid root `.env` credentials.
2. Open Safe Route Finder and analyze a Hyderabad route, e.g. Ameerpet, Hyderabad → Secunderabad, Hyderabad.
3. Confirm Route Results shows segment data; open map markers to inspect live/clear/unavailable signal states.
4. Open a segment diagnostics page and confirm the displayed factor breakdown sums to the segment's actual score.
5. Open Analytics; select an Exposure Field segment and a Risk Distribution bucket, then verify the shown roads match the loaded route.
6. Refresh the browser mid-session on Route Results, Segment Diagnostics, and Analytics, and confirm the route persists rather than resetting.
7. Download the route or saved-corridor safety report and compare its narrative and math against on-screen segment data.

## Known Limitations

- Saved Corridors is a frontend watchlist tied to loaded route checks; a server-side persistence API is future work.
- Waterlogging points and black spots are reference datasets and must be refreshed from authoritative sources for production use.
- Mapillary imagery can be unavailable for a specific street even with a valid token; local RDD2022 imagery is a fallback sample, not a location-matched image.
- News relevance depends on RSS indexing and road-name matching. No relevant headline is not evidence that an incident does not exist.
- The hazard advisory simulates movement over returned route geometry. It does not connect to a live vehicle GPS feed.
- Segment-to-segment comparison in Saved Corridors falls back to road-name/position matching when segment IDs don't align between checks, since IDs regenerate on every route recalculation rather than staying stable per road.
- Provider availability, quotas, and data quality remain external dependencies.
